## 0. Вердикт

- **Что это даёт:** рабочий метод, как собрать сложный продукт силами агента за ночь и не утонуть в ошибках: главное — заставить агента *доказывать*, что всё работает (скриншот каждой страницы, эмуляторы внешних API вместо настоящих). И отдельно — денежная находка: установка личных ИИ-агентов на сервер клиента — огромный интерес в поиске (OpenClaw — 415 тысяч запросов в месяц) и десятки гигов на Kwork и Fiverr.
- **Сигнал 7/10:** метод проверяемый и переносимый на любую работу с агентом; плюс гиг с доказанным спросом.
- **Смотреть самому?** Нет. Если хочется увидеть, как выглядят 350 скриншотов на PR, — `[15:26]–[16:33]`.

## 1. Что это открывает

- **Агент работает всю ночь до результата:** `/goal` в Claude Code держит агента в работе, пока не выполнено условие, — проверяет отдельная быстрая модель после каждого шага.
- **Условие «готово» = скриншоты:** «нет скриншота страницы — цель не достигнута». Агенту трудно соврать, вам легко проверить.
- **Эмуляторы вместо настоящих сервисов:** локальные копии API Slack, GitHub, Google (Gmail, Calendar, Drive), AWS — агент тестирует интеграции без банов и лимитов. Для сервиса, у которого эмулятора нет, агент пишет его сам за час.
- **Скриншоты на каждый PR + бот-мёрж:** внешние участники присылают PR, CI снимает скриншоты всех экранов, бот сам мёржит простые исправления. Так один человек ведёт проект со 100 участниками.
- **Готовый open-source продукт для установки клиентам:** Rakazo (лицензия Apache 2.0) — личный ИИ-агент со «своим компьютером», веб, десктоп и мобильное приложение.

## 2. Инструкция

### Что нужно (проверено 2026-10-16)

- Claude Code v2.1.139+ (там появился `/goal`; работает только в папке, которой вы дали доверие) или Codex CLI с тем же `/goal`.
- Playwright для скриншотов; для мобильного — Expo + Maestro.
- Эмуляторы: `npx emulate` от Vercel Labs — Vercel, GitHub, Google, Slack, Apple, Microsoft, AWS ([vercel-labs/emulate](https://skills.sh/vercel-labs/emulate/google)); для AWS — LocalStack.

### Шаги: продукт за ночь

**1. План** (≈ 1 час, вместе с агентом, Shift+Tab → режим плана):
```
Хочу построить <продукт>. Составь PLAN.md: экраны, данные, интеграции, порядок
работ чекбоксами. Принципы: любая модель (через одну библиотеку-адаптер), любой
провайдер песочницы/хостинга, ни одной жёсткой зависимости от внешнего сервиса —
всё за интерфейсами. Для каждой внешней интеграции — локальный эмулятор для тестов.
Запиши принципы в AGENTS.md, чтобы им следовал любой, кто добавляет функции.
```

**2. Эмуляторы внешних сервисов** (до запуска цели):
```bash
npx emulate --service github,slack,google      # Slack по умолчанию на :4003, Google на :4002
```
Для сервиса без эмулятора:
```
Сделай локальный эмулятор API <сервис>: те же эндпоинты и форматы ответов,
состояние в памяти (создал — потом можно прочитать), запуск одной командой.
Приложение в тестах ходит на него вместо настоящего API.
```

**3. Цель на ночь:**
```
/goal Все пункты PLAN.md отмечены. Для каждого экрана есть скриншот в screenshots/
на 375 и 1440 px, сделанный Playwright на работающем приложении. Все тесты зелёные
против эмуляторов. Без скриншота экран не считается готовым.
```
У автора первый запуск шёл всю ночь, понадобился второй `[04:19]`.

**4. Проверка безопасности** — `/security-review` в Claude Code (у автора — сторонний сканер).

**5. Скриншоты на каждый PR** (если проект живёт дальше):
```
Добавь GitHub Action: на каждый PR поднять приложение с эмуляторами, Playwright
снимает все экраны (светлая и тёмная тема, 375 и 1440 px), выкладывает как
артефакт и комментирует в PR те, что изменились.
```

### Шаги: установка Rakazo клиенту (основа гига ниже)

На сервере с Docker и Compose:
```bash
mkdir -p rakazo && cd rakazo
curl -fsSLO https://raw.githubusercontent.com/elie222/rakazo/main/infra/compose/install-images.sh
bash install-images.sh --prepare-only
# в .env: SANDBOX_PROVIDER и его ключ (по умолчанию локальный Docker), RAKAZO_HOST
bash install-images.sh
```
Затем HTTPS перед портом 5173 (Caddy или Nginx), создать аккаунт, подключить модель (OpenRouter, ключ Claude или подписку ChatGPT).

### Где споткнётесь

- **`/goal` без проверяемого условия = агент «решит», что всё готово.** Условие должно проверяться фактом (файлы скриншотов, зелёные тесты), а не словами.
- **Настоящие API в тестах** — баны и лимиты (Google блокирует автоматический вход). Поэтому эмуляторы ставятся *до* цели.
- **Звёзды и цифры автора** проверены частично: 4,3K звёзд на странице репозитория (в видео 3,7K — видео записано раньше). Про скриншоты на PR и бот-мёрж в README ничего нет — это его процесс, не часть продукта.
- **Установка агента клиенту = доступ к его серверу и ключам ИИ.** Ключи заводит клиент на свой аккаунт, вы их не храните; песочница агента — изолированный Docker.

### Где это продаётся

**Kwork — первым, но как проверку, а не как верный заработок:** интерес к личным агентам огромный (OpenClaw — 415 тысяч поисков в месяц), на Kwork 80 гигов, самый «сохраняемый» — 64 в избранном у продавца с 208 отзывами. Это значит, что опытные продавцы видят спрос, но сколько заказов именно на установку — публично не видно. Дешёвый пакет покажет это за две недели. Заходить не «ещё одним OpenClaw», а выбором и поддержкой: «OpenClaw или Rakazo — подберу под вас, с мобильным приложением, + месяц поддержки». **Fiverr — вторым:** «OpenClaw setup» уже забит, поэтому заходить именно Rakazo («the open-source Grok Bot alternative, installed on your server») — слово растёт, конкурентов по нему пока нет. **Upwork/Freelancer — для скриншот-тестов** стартапам, после 2–3 примеров в портфолио.

## 4. Крупнее: продукт

**Поддержка личных ИИ-агентов по подписке** (установка + обновления + «агент сломался — чиню»). Ворота: 1 — первый шаг: клиент даёт доступ к своему VPS незнакомцу ⚠️ (смягчается тем, что на Kwork это стандартная практика, и сервер можно поднять на аккаунт клиента с временным доступом); 2 — доверие: ключи ИИ клиента проходят через вашу установку ⚠️ (ключи заводит клиент сам); 3 — 1 500 ₽/мес × 20 клиентов = 30 000 ₽/мес ✅ маленько, но повторяемо; 4 — спрос измерим по заказам гига №1 ✅; 5 — канал: Kwork ✅; 6 — регуляторика: нет ✅. **Проходит условно** — проверяется гигом №1: если из первых 10 клиентов хотя бы 3 берут поддержку, это продукт.

## 6. Почему работает и сколько продлится

Рычаг: агенты стали достаточно сильными, чтобы строить ночью, но им нельзя верить на слово. Узкое место сместилось с «написать код» на «проверить, что он работает». Кто умеет превращать «готово» в проверяемый факт (скриншоты, эмуляторы, тесты), тот запускает больше и дольше спит. Это переживёт и Rakazo, и OpenClaw.

Окно по гигу: личные агенты — волна 2026 года (поиски «openclaw» выросли с нуля до 400 тысяч в месяц). Установка станет проще, и «просто поставлю» подешевеет за полгода-год. Останется поддержка и настройка под задачи клиента — поэтому сразу продавать с подпиской.

Вопрос: если доверие к ИИ строится на проверке, а не на вере, — где в вашей собственной работе вы до сих пор верите агенту на слово?
