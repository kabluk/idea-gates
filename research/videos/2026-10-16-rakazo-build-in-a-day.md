- Источник: https://www.youtube.com/watch?v=xk-aLMQRYfk&t=200s (Elie Steinbock, 2026-10-15, 19:53, 24.7K просмотров)
- Разобрано: 2026-10-16 · **сигнал 7/10**

## 0. Вердикт

- **Что это даёт:** рабочий метод, как собрать сложный продукт силами агента за ночь и не утонуть в ошибках: главное — заставить агента *доказывать*, что всё работает (скриншот каждой страницы, эмуляторы внешних API вместо настоящих). И отдельно — денежная идея с оговоркой: установка личных ИИ-агентов клиентам. Интерес огромный (OpenClaw — 415 тысяч поисков в месяц), но сам Rakazo уже ставится «скопируйте промпт — ваш агент сам всё установит» `[02:10]`, так что продавать стоит не установку, а настройку под задачи и поддержку.
- **Сигнал 7/10:** метод проверяемый и переносимый на любую работу с агентом; денежная часть — гипотеза, спрос на биржах не доказан.
- **Смотреть самому?** Нет. Если хочется увидеть, как выглядят 350 скриншотов на PR, — `[15:26]–[16:33]`.

## 1. Что это открывает

- **Агент работает всю ночь до результата:** `/goal` в Claude Code держит агента в работе, пока не выполнено условие, — по сторонним обзорам, после каждого шага выполнение условия проверяет отдельная быстрая модель ([inventivehq](https://inventivehq.com/blog/claude-code-goal-command-guide)).
- **Условие «готово» = скриншоты:** «нет скриншота страницы — цель не достигнута». Агенту трудно соврать, вам легко проверить.
- **Эмуляторы вместо настоящих сервисов:** локальные копии API Slack, GitHub, Google (Gmail, Calendar, Drive), AWS — агент тестирует интеграции без банов и лимитов. Для сервиса, у которого эмулятора нет, агент пишет его сам — так автор сделал эмуляторы для Composio и Daytona `[12:40]`.
- **Скриншоты на каждый PR + бот-мёрж:** внешние участники присылают PR, CI снимает скриншоты всех экранов, бот сам мёржит простые исправления. Так один человек ведёт проект со 100 участниками.
- **Готовый open-source продукт для установки клиентам:** Rakazo (лицензия Apache 2.0) — личный ИИ-агент со «своим компьютером», веб, десктоп и мобильное приложение.

**Уроки и ошибки автора:**
- ИИ пишет слишком много поясняющего текста в интерфейсе — у автора отдельный бот, который регулярно его вычищает `[18:12]`.
- Бот-мёрж не пропускает большие функции: присылает скриншоты и ждёт решения человека `[17:39]`.
- GitHub Actions для open-source бесплатны — поэтому 350 скриншотов на каждый PR ему ничего не стоят `[16:00]`.
- Выбор модели почти не важен: план — GPT 5.6, сборка — Grok 4.6, «потому что вышла в тот день» `[14:19]`.

**Ещё важное, сказанное мимоходом:**
- Rakazo ставится сам: «скопируйте этот промпт — ваш агент всё установит», плюс опубликованы приложения в App Store и Google Play `[01:37]–[02:10]`. Это прямо бьёт по гигу «установлю за вас».
- Главный довод против конкурентов: OpenClaw и Homeys «довольно сложно настроить» `[00:33]` — это и есть продающая мысль для услуги настройки.
- UI собран в Claude Design, а UX скопирован у продукта, который уже решил сложные вопросы (Grok Bot) `[03:46]–[04:19]` — сознательный приём: не изобретать интерфейс.
- Бот-мёрж — cron-задача раз в несколько часов, не пропускает вредоносные PR, может работать в GitHub Actions на существующих подписках Claude, Cursor или Codex `[17:06]`, `[18:12]–[18:46]`.

**Мнение, которое стоит отслеживать:** «дальше всех с ИИ продвигаются те, у кого больше всего доверия к нему и больше воображения» `[19:21]` — и доверие строится на проверке.

**Настоящий бизнес за видео:** Rakazo — бесплатный open-source, а зарабатывает автор на Inbox Zero. Open-source аналог горячего продукта (Grok Bot) дал 3,7K звёзд на момент записи (видео загружено 2026-10-15; 4,3K на 2026-10-16), сотню участников и внимание к основному продукту. **Это отдельная модель: «open-source клон хайпового продукта как маркетинг своего бизнеса».**

## 2. Инструкция

### Что нужно (проверено 2026-10-16)

- Claude Code v2.1.139+ (там появился `/goal`; работает только в папке, которой вы дали доверие) или Codex CLI с тем же `/goal`.
- Playwright для скриншотов (тесты Rakazo открыты в репозитории — их можно взять как образец `[18:46]`); для мобильного — Expo и, например, Maestro.
- Эмуляторы: `npx emulate` от Vercel Labs — Vercel, GitHub, Google, Slack, Apple, Microsoft, AWS ([vercel-labs/emulate](https://skills.sh/vercel-labs/emulate/google)); для AWS — LocalStack.

### Шаги: продукт за ночь

**1. План** (≈ 1 час, вместе с агентом, Shift+Tab → режим плана). Если похожий продукт уже существует, не изобретайте интерфейс — опишите, чей UX берёте за образец, и соберите экраны в Claude Design `[03:46]`:
```
Хочу построить <продукт>. Составь PLAN.md: экраны, данные, интеграции, порядок
работ чекбоксами. Принципы: любая модель (через одну библиотеку-адаптер), любой
провайдер песочницы/хостинга, ни одной жёсткой зависимости от внешнего сервиса —
всё за интерфейсами. Для каждой внешней интеграции — локальный эмулятор для тестов.
Запиши принципы в AGENTS.md, чтобы им следовал любой, кто добавляет функции.
```

**2. Эмуляторы внешних сервисов** (до запуска цели):
```bash
npx emulate --service github,slack,google      # Slack на :4003 [10:59]; Google на :4002 — по описанию пакета
```
Для сервиса без эмулятора:
```
Сделай локальный эмулятор API <сервис>: те же эндпоинты и форматы ответов,
состояние в памяти (создал — потом можно прочитать), запуск одной командой.
Приложение в тестах ходит на него вместо настоящего API.
```

**3. Цель на ночь:**
```
/goal Все пункты PLAN.md отмечены. Для каждого экрана есть скриншот в screenshots/
на 375 и 1440 px, сделанный Playwright на работающем приложении. Все тесты зелёные
против эмуляторов. Без скриншота экран не считается готовым.
```
У автора первый запуск шёл всю ночь, понадобился второй `[04:19]`.

**4. Проверка безопасности** — `/security-review` в Claude Code (у автора — сторонний сканер).

**5. Скриншоты на каждый PR** (если проект живёт дальше):
```
Добавь GitHub Action: на каждый PR поднять приложение с эмуляторами, Playwright
снимает все экраны (светлая и тёмная тема, 375 и 1440 px), выкладывает как
артефакт и комментирует в PR те, что изменились.
```

### Шаги: установка Rakazo клиенту (основа гига ниже)

На сервере с Docker и Compose:
```bash
mkdir -p rakazo && cd rakazo
curl -fsSLO https://raw.githubusercontent.com/elie222/rakazo/main/infra/compose/install-images.sh
bash install-images.sh --prepare-only
# в .env: SANDBOX_PROVIDER и его ключ (по умолчанию локальный Docker), RAKAZO_HOST
bash install-images.sh
```
Затем HTTPS перед портом 5173 (Caddy или Nginx), создать аккаунт, подключить модель (OpenRouter, ключ Claude или подписку ChatGPT).

### Где споткнётесь

- **`/goal` без проверяемого условия = агент «решит», что всё готово.** Условие должно проверяться фактом (файлы скриншотов, зелёные тесты), а не словами.
- **Настоящие API в тестах** — баны и лимиты (Google блокирует автоматический вход). Поэтому эмуляторы ставятся *до* цели.
- **Звёзды и цифры автора** проверены частично: 4,3K звёзд на странице репозитория (в видео 3,7K — видео записано раньше). Скриншот-тесты лежат в репозитории как Playwright-тесты `[18:46]` — их стоит взять за образец; бот-мёрж работает как cron-задача раз в несколько часов `[17:06]`, `[18:46]`. Сам автор emulate в Rakazo, по его словам, «кажется, не использует» `[10:24]`, и он контрибьютор emulate — учитывайте пристрастность.
- **Установка агента клиенту = доступ к его серверу и ключам ИИ.** Ключи заводит клиент на свой аккаунт, вы их не храните; песочница агента — изолированный Docker.

**Kwork — первым, но как проверку, а не как верный заработок:** интерес к личным агентам огромный (OpenClaw — 415 тысяч поисков в месяц), на Kwork 80 гигов, один гиг собрал 64 закладки — это единственный публичный сигнал по конкретному гигу; заказов не видно. ## 4. Крупнее: продукт

**Поддержка личных ИИ-агентов по подписке** (установка + обновления + «агент сломался — чиню»). Ворота: 1 — первый шаг: клиент даёт доступ к своему VPS незнакомцу ⚠️ (смягчается тем, что на Kwork это стандартная практика, и сервер можно поднять на аккаунт клиента с временным доступом); 2 — доверие: ключи ИИ клиента проходят через вашу установку ⚠️ (ключи заводит клиент сам); 3 — 1 500 ₽/мес × 20 клиентов = 30 000 ₽/мес ✅ маленько, но повторяемо; 4 — спрос можно измерить заказами гига №1, но пока не измерен ⚠️; 5 — канал: Kwork ✅; 6 — регуляторика: нет ✅. **Проходит условно** — проверяется гигом №1: если из первых 10 клиентов хотя бы 3 берут поддержку, это продукт.
