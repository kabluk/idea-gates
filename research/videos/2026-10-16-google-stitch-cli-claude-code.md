## 0. Вердикт

- **Одной фразой:** полезный рецепт «Claude Code управляет Google Stitch через новый CLI + независимая проверка-критик». Ценнее всего сам принцип «бриф → генерация → отдельный ревьюер», а не Stitch и не анимации.
- **Смотреть самому?** Нет. Весь процесс из 7 шагов целиком изложен в описании под видео. Если хочется увидеть руками, то только 02:44–06:30 (установка и бриф) и 09:25–10:55 (ревью-скилл).
- **Сигнал 5/10:** одна свежая и проверяемая новость (CLI), один переносимый принцип (критик отдельно от генератора), остальное — показ на одном демо-сайте.

## 1. Главная идея

Дизайн-инструмент Google Stitch получил CLI, поэтому им теперь управляет не человек, а Claude Code со своими скиллами. Качество даёт не сам Stitch, а цепочка вокруг него: письменный бриф, из которого идут все промпты, много итераций и отдельные скиллы-ревьюеры. Они ловят то, чего генератор не видит: поломку на телефоне и перебор анимаций.

## 3. Это ещё правда? (на 2026-10-16)

- **CLI существует — правда.** В npm есть официальный пакет [`@google/stitch`](https://www.npmjs.com/package/@google/stitch) «Agent-first CLI and MCP server for Google Stitch». Первая публикация — 2026-10-01, версия 0.11.1 от 2026-10-08. Команды из ролика (`npm install -g @google/stitch`, `stitch login`) совпадают с инструкцией по ссылке из описания. Оговорка: версия 0.x, то есть меньше трёх недель от роду; команды и флаги ещё будут меняться.
- **Stitch бесплатный — пока правда.** Это бета Google Labs: платного тарифа нет, с апреля 2026 действуют дневные кредиты (по данным [banani.co](https://www.banani.co/blog/google-stitch-pricing-and-credits) и [superdesign.dev](https://www.superdesign.dev/blog/google-stitch-review), точные цифры у источников расходятся). Восемь итераций на страницу съедают заметную часть дневного лимита. Бесплатность Labs-продукта — условие, которое может исчезнуть.
- **«MCP всегда висит в контексте» — устаревает.** В Claude Code MCP-инструменты уже умеют подгружаться по требованию (отложенные инструменты), так что разница в токенах меньше, чем говорят в ролике. Реальное преимущество CLI в другом — простота установки и входа.
- **Скилл Scrollytelling по ссылке существует** (файл открывается). Готовые ревью-скиллы самих авторов публично не выложены: они в платном сообществе.

## 4. Стратег: механизм

- **Рычаг:** агент с файловой системой (Claude Code) становится «дирижёром», а специализированные модели — его инструментами через CLI и скилл. Google не конкурирует с Claude Code, а встраивает в него Stitch, чтобы забрать дизайн-слой. Это та же модель, что и [stitch-skills от Google Labs](https://pyshine.com/Stitch-Skills-Google-Stitch-Agent-Skills-Design-to-Code/), теперь без настройки Cloud.
- **Кто забирает ценность:** Google получает пользователей Stitch (бесплатно, пока это Labs). Авторы ролика — подписки на платное сообщество со скиллами. Генерация бесплатная, поэтому дефицитным становится **вкус и проверка**: бриф и ревьюер.
- **Вторичный эффект:** когда тысячи зрителей соберут сайты по одному рецепту (Stitch + тот же scrollytelling-скилл), получится новый узнаваемый «AI-стиль»: космос, звёзды, горизонтальный таймлайн. Обещание «не как у всех» проживёт месяцы, а не годы.
- **Срок жизни:** сам трюк «CLI вместо MCP» — недели, его повторят все дизайн-инструменты. Принцип «генератор + отдельный критик + единый бриф» долговечен, и его можно переносить куда угодно, в том числе в ваши скиллы. Именно так устроены idea-gates (ворота отдельно от генерации идей) и video-advisor.

## 5. Бизнес-аналитик: идеи

**А. «Сайты-истории для малого бизнеса» на Claude + Stitch (услуга).**
1. Первый шаг: незнакомый владелец бизнеса должен заплатить вам за сайт — проходит, если есть портфолио; без него трудно.
2. Доверие: нужен доступ к домену и хостингу клиента — терпимо.
3. Мелкий клиент: ~$300–800 разово × 1 сайт = разовые деньги, без повторных платежей. Это услуга, а не масштабируемый продукт.
4. Измеримость: спрос на «сайты для X» проверяется дёшево.
5. Канал: **закрыто здесь.** Этот рецепт смотрят 56K человек, а через месяц его повторят сотни фрилансеров. Без своего канала вы соревнуетесь ценой на биржах. Профиля нет, поэтому оценка по умолчанию: «холодные продажи — нет».

**Б. Открытый скилл «design-review» (скриншоты на 3 ширинах + жёсткий критик) — как актив доверия, не как бизнес.**
1. Первый шаг: выложить на GitHub — ничьего согласия не нужно. ✅
2. Доверие: не нужно. ✅
3. Деньги: прямых денег ≈ 0. Ценность в аудитории и репутации, это ровно тот «актив доверия», которого обычно не хватает на воротах 1 и 2. ⚠️ Не бизнес сам по себе.
4. Измеримость: звёзды, установки, упоминания — бесплатно. ✅
5. Канал: GitHub, каталоги скиллов, ваш же README idea-gates. ✅
6. Регуляторика: нет. ✅
→ Проходит, но как вложение в репутацию. Авторы ролика прячут ровно эти скиллы за платной стеной, а открытая версия заберёт этот спрос.

**В. Применить у себя: быстрые лендинги для проверки идей.** Это не новая идея, а ускоритель уже существующего процесса idea-gates. Идея, прошедшая ворота, получает лендинг с формой записи за вечер, а не за неделю, и «грубый тест спроса» (ворота 4) дешевеет. Самый практичный вывод из видео.

## 6. План

- **Сегодня (≤ 1 час):** `npm install -g @google/stitch && stitch login`, поставить официальный Stitch-скилл в `.claude/skills/`. Попросить Claude Code: «Опроси меня и напиши brief.md для лендинга idea-gates, затем сделай в Stitch 3 варианта». Записать время и расход кредитов — это недостающие цифры, которых нет в ролике.
- **На этой неделе:**
  1. Сравнить вслепую: тот же бриф через Stitch и через Claude без Stitch. Готово, если вы можете честно сказать, какой лучше и насколько.
  2. Написать свой `design-review` скилл: Playwright-скриншоты на 375 / 768 / 1440 px и отчёт «худшее первым». Готово, если он поймал хотя бы одну поломку на телефоне.
  3. Решить, выкладывать ли его открыто (идея Б).
- **30 дней:** собрать лендинги для 2–3 идей, которые прошли ворота, с формой записи. Метрика: конверсия в запись на ~100 посетителей каждый. Бюджет: $0–100 на трафик, ~2 часа на лендинг. **Критерий остановки:** если лендинг отнимает больше 2 часов или Stitch не выигрывает слепое сравнение у Claude без него — убрать Stitch из цепочки и оставить только принцип «бриф + ревьюер».

## 7. Философ

- **Допущение:** вкус можно делегировать — достаточно второго промпта «будь строгим, как жюри Awwwards», и качество возникнет из количества итераций.
- **Сильнейший контраргумент:** ревьюер судит по тому же статистическому вкусу, что и генератор, поэтому оба сходятся к среднему «красивому». Кроме того, тяжёлые scroll-анимации часто ухудшают скорость, доступность и конверсию: для лендинга, проверяющего спрос, это минус, а не плюс.
- **Для вас:** если цель — проверять идеи, а не получать дизайн-награды, «впечатляющий» сайт может быть ловушкой перфекционизма.
- **Вопрос, над которым стоит подумать:** если машина делает восемь вариантов и сама выбирает лучший, что в этом процессе остаётся по-настоящему моим — и где моё решение меняет результат?
